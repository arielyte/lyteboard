## Android clipboard

On Android 10 and newer, clipboard reads are allowed for the focused app or the default input method. An ordinary Lyteboard app can therefore capture through an explicit action while its activity has input focus. A background worker or foreground-service notification supplies no input focus. Provide a visible copy action for history items with `ClipboardManager.setPrimaryClip()`. Android 13 and newer handle copy confirmation in the system UI. Set `ClipDescription.EXTRA_IS_SENSITIVE` for sensitive clips to hide their preview. The flag controls presentation. [Android 10 privacy changes](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data), [ClipboardManager](https://developer.android.com/reference/android/content/ClipboardManager), [Copy and paste](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste), [ClipDescription](https://developer.android.com/reference/android/content/ClipDescription#EXTRA_IS_SENSITIVE)

## UniFFI on Android

Describe the Rust interface using UniFFI procedural macros or UDL and generate Kotlin bindings with a generator version that matches the Rust dependency. Build the Rust library as a `cdylib` with the Android NDK for every supported ABI and package it as `lib/<abi>/lib<name>.so` in the APK. A phone and a local emulator commonly call for `arm64-v8a` and `x86_64` respectively, depending on the test host. The standard UniFFI JVM Kotlin bindings use JNA's Android AAR (documented minimum JNA 5.12.0). [UniFFI overview](https://mozilla.github.io/uniffi-rs/latest/), [Binding generation](https://mozilla.github.io/uniffi-rs/latest/bindings.html), [Kotlin integration](https://mozilla.github.io/uniffi-rs/latest/kotlin/gradle.html#jna-dependency), [Android ABIs](https://developer.android.com/ndk/guides/abis#native-code-in-app-packages)

## Linux clipboard and local IPC

- **X11.** Use the `CLIPBOARD` selection for explicit copy and paste. The owning X client serves the data when a requestor asks for it. XFixes can notify another client when that selection changes. Clipboard persistence after the owner exits requires another client to keep the data. [ICCCM clipboard selection](https://www.x.org/releases/current/doc/xorg-docs/icccm/icccm.html#The_CLIPBOARD_Selection), [XFixes protocol](https://www.x.org/releases/current/doc/fixesproto/fixesproto.txt)
- **Wayland.** Core `wl_data_device` delivers clipboard offers around keyboard focus. Background clipboard management depends on a compositor advertising and granting a data-control protocol such as staging `ext_data_control_manager_v1`. Detect availability at runtime and keep explicit in-app clipboard actions usable in sessions without background support. [Wayland core protocol](https://raw.githubusercontent.com/wayland-mirror/wayland/main/protocol/wayland.xml), [Wayland data-control protocol](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/staging/ext-data-control/ext-data-control-v1.xml)
- **Local socket.** Use a pathname Unix socket in a private directory under `$XDG_RUNTIME_DIR`. Validate the runtime directory's ownership and mode (0700). The daemon and each client verify the peer UID on the connected `AF_UNIX` stream with `SO_PEERCRED`. Filesystem permissions apply to pathname sockets. Abstract sockets have no filesystem permissions. This boundary authenticates the OS user. Processes with that UID share the user's access. [XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/latest/), [Linux unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html)

## Windows local IPC

Create a named pipe with an explicit DACL restricting access to the intended logon SID and set `PIPE_REJECT_REMOTE_CLIENTS`. Use `FILE_FLAG_FIRST_PIPE_INSTANCE` on startup so the daemon fails if the name is already in use. Microsoft's default pipe security descriptor includes read access for Everyone and Anonymous. Grant only the required rights. Generic write also includes the right to create a pipe instance. When the server needs to check client identity beyond the DACL, use the client's impersonation token, check impersonation success, and call `RevertToSelf` after the check. Clients also verify the connected server's OS identity before sending sensitive data. [Pipe access rights](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [CreateNamedPipe flags](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createnamedpipea), [Client impersonation](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient), [Named pipe server process ID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid)
